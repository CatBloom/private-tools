private-tools 要件書

個人用ユーティリティアプリ（初版）／ 2026-08-27 時点

1. 目的と方針

個人用のWebアプリを、本番環境で安全に運用しながら継続的に拡張できる共通基盤を構築する。

初版は、特定の業務機能を完成させることではなく、認証・デプロイ・データ保存・CI/CDを備えた土台を構築することを主目的とする。具体的な機能はGitHub Issue単位で追加・改善する。

個人利用 モバイル優先 本番環境のみ 段階的拡張

2. 対象範囲

区分内容
含む認証済み利用者向けのWeb画面、将来のデータ保存機能を追加できる基盤、CI/CD。
含むスマートフォンでの操作を主眼に置いたレスポンシブUI。PCでも支障なく利用できること。
含まない（初版）アプリ内アカウント作成・ユーザー管理、複数利用者対応、ブラウザ側暗号化、外部サービスからのプロンプト自動取得。

3. 構成

領域採用内容役割
アプリHono SSR + React + Vite + TypeScript画面表示、フォーム処理、サーバー側API処理。
ホスティングVercel本番アプリのデプロイと実行。
データ保存Cloudflare Workers KVCSV、テキスト、メタデータの保存。
KV接続Cloudflare KV REST APIVercel上のアプリがサーバー側からKVに接続する。Cloudflare Workersは初版では使用しない。
アクセス制御Cloudflare Accessアプリへのアクセスを許可済みのGoogleアカウントに限定する。
ドメインcatbloom.netAWSで登録管理を継続し、CloudflareでDNS管理する。利用サブドメインは未決定。
ソース管理GitHub新規リポジトリ CatBloom/private-tools（予定）。

KVへのAPIトークンはVercelの環境変数にのみ保存し、クライアントJavaScript・Gitリポジトリ・ログへ出力しない。

4. 将来追加する機能の例

クレジットカード明細CSV

  • Web画面からCSVファイルをアップロードできること。
  • アップロードしたCSVを保存し、必要時に読み込めること。
  • 既存 credit-csv-viewer と同等の考え方を参照して明細を閲覧できること。
  • CSVファイルは1件25 MiB以下、KVの保存総量は1 GB以下を初期運用上の制約とする。

プロンプト管理

  • NovelAIなどで使うプロンプトを手入力で保存できること。
  • 保存済みの要素を選んで組み合わせ、結果をコピーできる構成を将来の基本機能例とする。
  • 正・ネガティブプロンプト、タグ、テンプレート、並び順などの詳細はIssueで決める。

画面構成（暫定）

  • ホーム／機能一覧
  • CSV明細ビューア
  • プロンプト管理

5. 非機能要件

  • 利用者は本人のみを想定する。アプリ内ユーザー登録は実装しない。
  • Cloudflare Accessで認証を必須とし、Googleアカウントでのログインを第一候補とする。許可するメールアドレスは設定時に指定する。
  • アクセス保護は初版の必須要件。保存データのブラウザ側暗号化は将来要件とする。
  • モバイル画面では、横スクロールや小さすぎる操作要素を避ける。
  • KVは結果整合性ストアであるため、同一データを複数端末から同時編集しない前提とする。
  • 利用料金は無料枠内に収めることを基本条件とする。AWSのRoute 53ホストゾーン料金のように、運用上必要な極少額の定額課金は許容する。
  • 従量課金や無料枠超過による想定外の課金は避ける。導入するサービスごとに、無料枠・固定費・超過時の挙動を確認する。

6. 利用者が行う事前準備

外部サービスのアカウント作成、契約、管理画面での設定、秘密情報の登録、デプロイ操作は利用者が行う。Codexは各作業に必要なコード、設定値の名称、確認手順を提示する。

順序サービス準備内容完了条件
1 GitHub GitHubアカウントで、新しい非公開リポジトリ CatBloom/private-tools を作成する。 main ブランチへコードを登録できる。
2 Vercel Vercelアカウントを作成し、GitHubアカウントを連携する。初回コードをGitHubへ登録した後、private-tools を新規プロジェクトとしてインポートし、本番ブランチを main に設定する。 GitHub連携が完了し、初回コード登録後にプロジェクトをインポートできる。
3 Cloudflare Cloudflareアカウントを作成し、多要素認証を有効にする。Freeプランで catbloom.net を追加する。既存DNSレコードを移行前に記録し、メールや既存サービスのレコードを含めてCloudflare側へ登録する。 Cloudflareから、catbloom.net 用のネームサーバーが発行される。
4 AWS AWSのドメイン登録管理画面で、catbloom.net のネームサーバーをCloudflare指定値へ変更する。DNS切替が完了するまで、既存のRoute 53ホストゾーンは削除しない。 Cloudflare上でドメインがActiveとなり、既存のDNS利用に問題がない。
5 本番URL catbloom.net 配下のサブドメインを決定し、VercelのCustom DomainとCloudflare DNSに設定する。候補は tools.catbloom.net とする。 決定したHTTPS URLでVercelのアプリへ到達できる。
6 Cloudflare Access Cloudflare Zero Trustを開始し、本番URLをSelf-hosted applicationとして登録する。本人のメールアドレスだけを許可するAccessポリシーを作る。認証方式はGoogleを第一候補とし、Google採用時はGoogle CloudでOAuthクライアントを作成してCloudflareへ登録する。簡素化する場合はメールのワンタイムコードも選択できる。 未認証ではアプリを閲覧できず、許可した本人のアカウントだけがログインできる。
7 Cloudflare Workers KV 本番用KV Namespaceを作成する。利用するCloudflareアカウントに限定し、必要な Workers KV Storage Read／Write 権限だけを持つAPIトークンを発行する。Account IDとNamespace IDを控え、Global API Keyは使用しない。 KVのAccount ID、Namespace ID、APIトークンをVercelへ登録できる。
8 Vercel環境変数 Codexが指定する名前で、CloudflareのAccount ID、KV Namespace ID、APIトークンをProduction環境へ登録する。値はGitHub、Issue、チャット、ソースコードへ記載しない。 Vercel上のサーバー処理からKVを読み書きでき、秘密値がブラウザへ公開されない。
9 料金確認 VercelとCloudflareが無料プランであること、AWSのドメイン更新料やRoute 53ホストゾーンなどの固定費を確認する。従量課金を有効にする場合は、事前に上限・通知・超過時の挙動を確認する。 想定する月額固定費と、課金が発生し得る条件を把握している。

APIトークン、OAuth Client Secret、各サービスのパスワードや復旧コードは要件書に記載しない。各サービスの秘密情報管理画面またはパスワードマネージャーで保管する。

公式手順：Cloudflareへのドメイン追加、AWSでのネームサーバー変更、Cloudflare AccessのGoogle認証、Workers KV、VercelとGitHubの連携。

7. CI/CD と運用分担

契機実行内容
Pull Request作成・更新自動テストを実行する。必要に応じてVercel Preview Deploymentを利用する。
main へのマージ自動テスト成功を条件に、本番環境へ自動デプロイする。
機能追加GitHub Issueで要件を定義し、PRで実装・レビュー可能な単位に分ける。
担当内容
Codexアプリコード、テスト、GitHub Actionsなどの設定ファイル、デプロイ手順書を作成・更新する。
利用者GitHub、Vercel、Cloudflare、AWSのアカウント作成・連携・実際のデプロイ・秘密情報の登録を行う。

8. 今後、Issueで決める事項

  • 対応するカード会社・CSVフォーマット、表示列、検索・集計・カテゴリなどのCSV詳細機能。
  • CSVの削除、置換、保持期間、バックアップ方針。
  • プロンプトのデータ項目、合成ルール、画面設計。
  • 使用するサブドメイン名とCloudflare DNS／Accessの具体的な設定値。
  • Cloudflare Accessで許可するGoogleアカウントの確定。
  • KV容量・ファイルサイズを超えた場合のR2移行、および複数端末での同時編集が必要になった場合のD1移行。
  • ブラウザ側暗号化、監査・バックアップなどの追加セキュリティ要件。
